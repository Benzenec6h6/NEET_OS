* Overview

*NEET_OS* is an independent, opinionated operating system built on top of the Nix ecosystem. While it leverages Nix modules for declarative configuration, it completely replaces the standard systemd userland with a lightweight, modern, and high-performance stack:

- **Init & Service Manager:** =s6= + =s6-rc= supervised service tree.
- **Device Management:** =mdevd= / =gardendevd= (fast and minimal udev alternatives).
- **Core Toolchain (=inieet=):** Custom Rust-based activation, boot synchronizer, mount orchestrator, and helper tooling.
- **Display Protocol:** Pure Wayland (Hyprland / Sway).
- **Storage & Boot:** Modern UEFI-first architecture (Limine / EFISTUB / UKI, Secure Boot, TPM2, LUKS, and Btrfs with impermanence reset).

* Crucial Rules & Constraints

Please keep these architectural principles in mind when configuring NEET_OS:

*** 1. UEFI Only (No Legacy BIOS / CSM)
NEET_OS targets modern UEFI systems exclusively. Legacy BIOS / CSM boot modes are not supported.

*** 2. Pure Wayland Only (No X11 Sessions)
The desktop stack is strictly Wayland-native. Native X11 sessions are not provided. (XWayland is available for individual app compatibility where required).

*** 3. DO NOT use =exec-once= in Window Managers
Do *not* launch background services, daemons, or long-running processes using window manager autostart commands (e.g., =exec-once= in Hyprland or =exec= in Sway).
- **Why?** Processes spawned directly by the compositor cannot be tracked or safely supervised across generational switches.
- **Recommended Approach:** Declare your background tasks as **s6-rc user services** (~modules/init/s6-rc/user.nix~). This guarantees proper dependency management, supervision, and clean restarts during system rebuilds.

* Daily Operations & Workflow

NEET_OS provides a unified CLI front-end, =neet os= (backed by =neet-helper= and underlying scripts like =neet-rebuild= / =neet-gc=).

The default flake path is =/etc/neet-os= (can be overridden via the =NEET_FLAKE= environment variable).

*** Rebuilding & Switching Generations
To build your system configuration and apply changes:

#+begin_src sh
# Build, inspect the diff interactively, and switch
neet os switch

# Skip interactive prompt
neet os switch --yes

# Force live switch even if kernel/drivers have changed
neet os switch --force

# Target a custom flake directory or specific attribute
neet os switch /path/to/flake --attr packages.x86_64-linux.default
#+end_src

#+begin_quote
[!TIP]
**Safe Live Switching:** NEET_OS automatically compares kernel, firmware, module, and graphics driver manifests. If critical components have changed, live switching is safely skipped to avoid application crashes, and you will be prompted to reboot.
#+end_quote

*** Inspecting Configuration Differences
To preview package and service differences before applying them:

#+begin_src sh
neet os diff
#+end_src

*** Next-Boot Switching
If you want to stage a new generation for the next bootloader reboot without touching the running environment:

#+begin_src sh
neet os boot
#+end_src

*** Listing System Generations
#+begin_src sh
neet os list
#+end_src

*** Garbage Collection
Remove older system generations, prune the Nix Store, and automatically synchronize bootloader/EFI entries:

#+begin_src sh
# Keep the latest 5 generations (default)
neet os gc

# Keep only the last 3 generations
neet os gc +3

# Purge generations older than 30 days
neet os gc 30d
#+end_src

*(Direct scripts =neet-rebuild= and =neet-gc= are also available under the system module).*

* Repository Structure

- =modules/= - Declarative configurations (boot, disks, filesystems, init, hardware, services, security).
  - =modules/init/s6-rc/= - s6-rc compiled database definitions and user service supervision.
- =pkgs/inieet/= - Custom Rust toolchain:
  - =neet-activate=: Generational filesystem, etc, wrapper, and service activation engine.
  - =neet-helper=: High-level CLI for builds, diffs, switching, and GC.
  - =neet-mount=: Stage-1 mounts and Btrfs impermanence rollback.
  - =neet-secret=: TPM2-backed secret decryption.
  - =limine-install= / =esp-sync= / =efistub-sync=: Bootloader entry management.
- =diary.org= - Historical development logs and notes.

* Roadmap / Planned Features

NEET_OS is under active development. The following features are currently being designed and implemented:

- **Intelligent Impact Analysis (=neet-helper=):**
  - Implement static dependency evaluation during builds to classify changes into three action levels:
    1. *Seamless (Live Switch):* Safely reload running services with zero user disruption.
    2. *Relogin Required:* Prompt session restart when Wayland, PAM, or core session environments change.
    3. *Reboot Required:* Block live switching and require a reboot when the kernel, initrd, firmware, or graphic drivers change.
- **Per-User Isolated s6-rc Services:**
  - Decouple user service definitions, allowing individual users to declare and supervise their own dedicated s6-rc services and dependency trees independently from the global system database.
- **Automated Lifecycle Management:**
  - Deep integration between =neet-helper= and =fcron= to enable automated, non-intrusive background updates and declarative garbage collection (=neet os gc=).
